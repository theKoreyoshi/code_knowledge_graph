## 1. 加一种关系

以"记录函数对全局变量的**取地址**"为例。

### 步骤 1：登记类型

`ckg/graph_builder.py`：

```python
RELATION_DESCRIPTIONS = {
    ...
    "ADDRESS_OF": "函数取了变量/字段的地址",
}
```

同时（如果可视化里要单独配色）在 `ckg/visualize.py` 的
`REL_COLORS` / `REL_LABELS` 里加一项。不加也能跑，会落到默认灰色。

### 步骤 2：在抽取器里产出边

`ckg/extract_clang.py` 的 `_access_mode()` 已经把 `&` 识别出来（返回 `"read"`）。
要专门记一条边，在 `_on_decl_ref()` 里加分支：

```python
if mode == "read" and self._is_address_of(cursor, path):
    if self._edge_once(owner, target, "ADDRESS_OF", site):
        self.graph.edge(owner, target, "ADDRESS_OF",
                        line=loc.line, file=self.rel_path(loc.file), sites=[site])
```

要点：

- **一定要用 `_edge_once()` 去重**。同一个 (head, rel, tail, 站点) 会被多个翻译单元重复产出；
- 边属性里带上 `line` / `file`，可视化与报告都能用；
- `sites` 传**列表**，`graph.edge()` 会把它打平去重。

### 步骤 3：加断言

`tools/validate.py` 的对应 case 里加一条：

```python
("edge", "ADDRESS_OF", "some_function", "some_variable"),
```

跑 `python tools/validate.py`，通过即可。

### 关系类型一览（现成可抄）

| 关系 | 产出位置 |
| --- | --- |
| `CONTAINS` / `HAS_PARAMETER` / `HAS_VARIABLE` / `HAS_MEMBER` / `HAS_METHOD` | `_on_declaration()`、`_link_method_to_class()` |
| `CALLS` / `CALLS_PTR` / `CALLS_MACRO` | `_on_call()`、`finalize_macros()` |
| `READS` / `WRITES` | `_on_decl_ref()`、`_on_member_ref()` |
| `ASSIGNED_TO` | `_record_function_assignment()` |
| `TYPE_OF` / `RETURNS` / `TYPEDEF_OF` | `_type_targets()` 的调用点 |
| `INHERITS` | `_on_base_specifier()` |
| `INCLUDES` | `_collect_includes()` |
| `USES_MACRO` / `MACRO_DEPENDS_ON` / `MACRO_ALIAS` / `GENERATES` | `finalize_macros()` |

## 2. 加一种实体类型

以"函数式宏的参数"为例。

### 步骤 1：声明 cursor kind → 实体类型

`ckg/extract_clang.py`：

```python
DECL_KIND_TO_ENTITY = {
    ...
    capi.CXCursor_SomeDecl: "SOMETHING",
}
```

若这是"类函数"或"类类型"声明，同时加进 `FUNCTION_LIKE_KINDS` / `TYPE_LIKE_KINDS`，
这样它们会被当作函数/类型参与调用图与类型解析。

### 步骤 2：补 descriptions

`ckg/graph_builder.py` 的 `ENTITY_DESCRIPTIONS` 加一行，报告与界面会自动带上中文名。

### 步骤 3：在 `_on_declaration()` 里处理

按已有分支的样子写：取名字、位置，调 `declared_node()` 拿（或创建）节点 id，
然后连边。父节点用 `self._owner(path)`。

### 步骤 4：可视化配色

`ckg/visualize.py` 的 `TYPE_COLORS` / `TYPE_LABELS` 各加一项，
`ckg/templates/graph.js` 不需要改（它是数据驱动的）。

## 3. 支持新语言

分两种情况。

### 3.1 clang 家族（Objective-C / CUDA / OpenCL …）

`ckg/languages.py` 里已有 `objective-c` / `objective-c++`。
新增语言只需加扩展名映射：

```python
_BY_EXTENSION = {
    ...
    ".cu": Language("cuda", "cuda", "cpp"),
}
```

`clang_kind` 会作为 `-x` 的值传给编译器；`tree_sitter` 字段用于语法层
（没有对应 grammar 时填 `""`）。

### 3.2 其它语言（Python / Java / Go …）

clang 前端不适用，需要新增一个纯 tree-sitter 引擎，做法参考
`ckg/extract_treesitter.py`：

1. 在 `languages.py` 登记语言与 tree-sitter grammar 名；
2. 在 `languages.tree_sitter_grammar()` 里返回对应 `Language` 对象
   （需要 `pip install tree-sitter-python` 之类的 grammar 包）；
3. 写 `ckg/extract_python.py`，遍历语法树产出节点与边，
   实体类型可复用 `FUNCTION` / `CLASS` / `VARIABLE`，也可自定；
4. 在 `pipeline.py` 里按文件语言分派到对应引擎；
5. 在 `tools/validate.py` 加一个 Python 工程用例。

clang 专属能力（类型解析、宏展开、真实预处理）在纯语法层不存在，
因此新语言下的 `TYPE_OF`、`USES_MACRO` 之类关系需要另行设计。

## 4. 加一个构建系统

`ckg/autoconfig.py` 里加一个 `_from_xxx(detection, source_root)`，
在 `detect()` 的优先级链里插入，并更新 `Detection.provider` 候选值。

模板：

```python
def _from_bazel(detection: Detection, source_root: str) -> None:
    path = os.path.join(source_root, "BUILD.bazel")
    if not os.path.isfile(path):
        return
    detection.evidence.append("BUILD.bazel")
    text = _read(path)
    includes, defines = [], []
    for match in re.finditer(r"includes\s*=\s*\[([^\]]*)\]", text):
        for token in re.findall(r'"([^"]+)"', match.group(1)):
            _push_path(includes, source_root, token)
    for match in re.finditer(r"copts\s*=\s*\[([^\]]*)\]", text):
        for token in re.findall(r'"-D([^"]+)"', match.group(1)):
            defines.append(token)
    if includes or defines:
        detection.provider = "bazel"
        detection.include_dirs = _dedupe(includes)
        detection.defines = _dedupe(defines)[:64]
```

`_push_path()` 会校验目录是否真实存在、把相对路径按 base 转成绝对路径，
一定要用它，否则会把一堆不存在的路径塞进 `-I`。

## 5. 改自动修复规则

`ckg/shimgen.py` 顶部是一组正则，`_apply()` 里是"诊断 → 合成内容"的映射。
新增规则的完整流程：

1. 在文件顶部加正则，例如
   `MEMBER_OF_UNKNOWN_RE = re.compile(r"member reference base type '([^']+)' is not a structure")`；
2. 在 `_inspect()` 里加分支，把命中的符号记进 `findings`（key 形如 `kind:name`）；
3. 在 `_apply()` 里加对应的生成逻辑，并写进 `self.typedefs/functions/variables/macros`；
4. 别忘了 `_write_prelude()` 要输出新内容（它按字典分类输出）。

注意两点：

- 生成物必须**只增不减**、且能写成合法 C（C++ 兼容），否则会让后续解析更糟；
- 达到 `MAX_SYNTHETIC` 后会停止生成，避免在极度残缺的输入上失控。

## 6. 换 / 加一个前端

当前前端是 libclang（`clang_capi.py` + `frontend.py` + `extract_clang.py`）。
如果想换成 `clang -Xclang -ast-dump=json`（版本无关、但需要自己处理 JSON AST），
建议：

1. 新建 `ckg/extract_json_ast.py`，实现与 `ClangExtractor` 相同的产出接口
   （`graph.nodes` / `graph.edges` / `macro_defs` / `expansions` / `diagnostics`）；
2. 在 `pipeline.py` 里加 `--frontend` 开关做分派；
3. `finalize_macros()`、`graph_builder`、`visualize`、`report` 都不用改 ——
   这是当初把"抽取"和"建图"分开的原因。

## 7. 自定义可视化

`ckg/templates/graph.html`（结构 + 样式）与 `ckg/templates/graph.js`（渲染逻辑）
是纯静态文件，`visualize.py` 只做占位符替换：

```python
script.replace("__TYPE_COLORS__", json.dumps(TYPE_COLORS))
      .replace("__REL_COLORS__",  json.dumps(REL_COLORS))
      .replace("__PRESETS__",     json.dumps(PRESETS))
```

常见改造：

- **加一个视图预设**：改 `visualize.py` 的 `PRESETS`（指定 `types` 与 `rels` 集合）；
- **改配色/标签**：改 `TYPE_COLORS` / `REL_COLORS` / `TYPE_LABELS` / `REL_LABELS`；
- **改节点大小/物理参数**：`graph.js` 里的 `radius()`、`state.repulsion`、
  `ideal`（弹簧自然长度）。

节点数据是 `visualize._node_payload()` 白名单挑字段，要展示新字段就得加进那个元组。

## 8. 性能调优 checklist

解析慢时按顺序排查：

1. `-j N` 是否用上（`run_meta.json` 里 `clang pass` 的 worker 数）；
2. 是否有超大文件（单文件几万行）—— 考虑用 `excludes` 排除或拆分分析；
3. 是否重复 tokenize —— 新增的抽取逻辑尽量复用 `_binop_cache` / `_unop_cache` 模式；
4. `_access_mode()` 的祖先链扫描是否被无意义地调用（只在 `DeclRefExpr` / `MemberRefExpr` 上调用）；
5. `clang -E` 是否必要（`--no-preprocess` 可省掉约 15% 时间，但会失去真实展开文本）。
